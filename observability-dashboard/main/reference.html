API Reference

HTTP Endpoints

Trace Ingestion

POST /v1/traces

Receives OpenTelemetry traces in protobuf or JSON format.

Request Headers:

Header Required Description

Content-Type

Yes

application/x-protobuf or application/json

Authorization

No

Bearer token for authenticated requests

X-Request-ID

No

Unique request identifier for tracing

Request Body:

OpenTelemetry traces following the OTLP specification.

Example Request (JSON):

{
  "resource_spans": [
    {
      "resource": {
        "attributes": [
          {
            "key": "service.name",
            "value": {"string_value": "my-agent"}
          }
        ]
      },
      "scope_spans": [
        {
          "spans": [
            {
              "trace_id": "1234567890abcdef1234567890abcdef",
              "span_id": "abcdef1234567890",
              "name": "agent.start",
              "start_time_unix_nano": 1640995200000000000,
              "end_time_unix_nano": 1640995201000000000,
              "attributes": [
                {
                  "key": "conversation.id",
                  "value": {"string_value": "123e4567-e89b-12d3-a456-426614174000"}
                },
                {
                  "key": "agent.name",
                  "value": {"string_value": "weather-agent"}
                }
              ]
            }
          ]
        }
      ]
    }
  ]
}

Response:

{
  "status": "success",
  "traces_received": 1,
  "spans_processed": 1,
  "events_created": 1,
  "processing_time_ms": 15
}

WebSocket Endpoints

Global Event Stream

WS /ws

Subscribe to the global event stream receiving all events.

Connection:

const ws = new WebSocket('ws://localhost:8000/ws');

Authentication (Optional):

const ws = new WebSocket('ws://localhost:8000/ws', [], {
  headers: {
    'Authorization': 'Bearer your-jwt-token'
  }
});

Message Format:

All messages are JSON objects with this base structure:

{
  "event_type": "string",
  "conversation_id": "uuid4",
  "timestamp": "iso8601",
  "trace_id": "string",
  "span_id": "string",
  "agent_name": "string",
  "metadata": {}
}

Connection Lifecycle:

  1. Connection Established: Client receives connection confirmation

  2. Event Stream: Continuous stream of events as they occur

  3. Error Handling: Connection closed with appropriate status codes

  4. Cleanup: Server cleans up resources on disconnect

Conversation-Specific Stream

WS /ws/{conversation_id}

Subscribe to events from a specific conversation.

Parameters:

Parameter Type Description

conversation_id

UUID4 string

Valid UUID4 format (36 characters)

Connection:

const conversationId = '123e4567-e89b-12d3-a456-426614174000';
const ws = new WebSocket(`ws://localhost:8000/ws/${conversationId}`);

Conversation ID Validation: - Format: ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$ - Case insensitive - Fixed length: 36 characters

Event Schemas

Base Event Structure

All events inherit from this base structure:

{
  "event_type": "string",           // Required: Event type identifier
  "conversation_id": "uuid4",       // Required: Conversation UUID4
  "timestamp": "iso8601",           // Required: Event timestamp (UTC)
  "trace_id": "string",            // Required: OpenTelemetry trace ID
  "span_id": "string",             // Required: OpenTelemetry span ID
  "agent_name": "string",          // Required: Name of the agent
  "metadata": {}                   // Optional: Additional event data
}

Field Specifications:

Field Type Required Description

event_type

string

✓

One of: agent.start, agent.stop, agent.message, llm.call, tool.output, error

conversation_id

UUID4

✓

Valid UUID4 string identifying the conversation

timestamp

ISO8601

✓

RFC3339 formatted timestamp in UTC (e.g., 2024-01-01T12:00:00.000Z)

trace_id

string

✓

32-character hex string (OpenTelemetry trace ID)

span_id

string

✓

16-character hex string (OpenTelemetry span ID)

agent_name

string

✓

Agent identifier (max 100 characters, alphanumeric and hyphens)

metadata

object

Event-specific additional data

Security Specifications

Authentication

JWT Token Structure:

{
  "header": {
    "alg": "HS256",
    "typ": "JWT"
  },
  "payload": {
    "user_id": "user123",
    "conversation_ids": ["uuid1", "uuid2"],
    "permissions": ["read:global", "write:traces"],
    "iat": 1640995200,
    "exp": 1640998800
  }
}

Supported Algorithms: - HS256 (HMAC with SHA-256) - RS256 (RSA with SHA-256) - planned

Input Validation

Conversation ID Validation: - Format: UUID4 (RFC 4122) - Length: 36 characters - Pattern: ^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$

Content Size Limits: - HTTP request body: 10MB - WebSocket message: 1MB - String fields: 4096 characters - Array fields: 1000 items

Content Filtering: - HTML/script tags removed - Special characters escaped - Binary data rejected in text fields
